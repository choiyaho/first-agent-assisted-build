## 0. 출발점 (주제 제안 원문)

> 소규모 카페 사장님이 메뉴 가격을 정할 때 쓰는 웹앱. 재료 원가, 판매가, 예상 판매량을 넣으면 마진과 손익분기점을 보여준다. 주변 카페는 "이 정도로 장사하니까"라는 감으로 가격을 정하는 경우가 많아서, 숫자를 근거로 판단할 수 있게 한다.
> - 기능 1: 메뉴별 원가·마진 계산
> - 기능 2: 월 고정비 기준 손익분기 판매량 계산
> - 기능 3: 가격·판매량 시나리오 비교

교수님 코멘트: 기능 구현은 간단하니 UI/UX 설계에 힘을 실을 것 → 계산은 가볍게, 화면 흐름과 읽기 쉬움에 집중한다.

2026-10-20 수정: 기능 1을 "레시피로 원가를 계산하고 희망 판매가의 마진을 보여주는 메뉴 조회"로 바꾸고, 재료 단가는 네이버 쇼핑 검색 결과에서 NVIDIA 무료 LLM이 골라 찾는다. 기능 2·3은 보류.

## 2. 정의 결정

| ID | 결정 | 선택지 | 내 선택 | 이유 |
|---|---|---|---|---|
| D1 | 원가 입력 방식 | (a) 1잔 원가 직접 입력 (b) 재료 구매가·구매량 + 1잔 사용량으로 환산 (c) 레시피 × 검색 단가 | (c) 1잔 원가 = Σ(레시피 용량 × 구매가 ÷ 구매량) + 포장비. 레시피는 recipe.csv, 구매가·구매량은 검색(D10) 후 사장이 확인·수정 | 2026-10-20 (a)→(c) 변경. 사장이 1잔 원가를 직접 알기 어렵다 |
| D2 | 1잔 변동원가에 넣을 것 | 재료 / 포장재 / 판매가 비례 비용(%) / 폐기·손실 | 재료(레시피) + 포장비(1잔 공통 고정값, 기본 300원, 사이드바에서 수정) + 카드 수수료(%, 앱 전체 하나) | 포장비는 메뉴마다 거의 같아 하나로 둔다. 수수료는 매 잔 붙는 실제 비용 |
| D3 | 부가세 | (a) 판매가 ÷ 1.1(공급가)로 계산 (b) 무시하고 한계에 적음 | (a) 판매가는 부가세 포함가. 이익은 공급가 기준, 수수료는 판매가 기준. 일반과세자 가정 | 무시하면 1잔 이익이 약 9% 크게 나온다 |
| D4 | 마진 표기 | 1잔 이익(원) / 원가율 / 마진율 / 마크업 (용어 정의 포함) | 1잔 이익 = 희망 판매가÷1.1 − 1잔 원가 − 희망 판매가×수수료율. 원가율 = (1잔 원가 + 수수료) ÷ 희망 판매가. 마진율 = 1잔 이익 ÷ 희망 판매가 | 분모를 메뉴판 가격으로 해서 사장이 바로 이해. 원가율+마진율 = 90.9%(나머지는 부가세) |
| D5 | 손익분기 기준 | (a) 메뉴 하나 기준 (b) 판매 비중 가중 전체 잔 수 (c) 손익분기 매출액 | **보류** (2026-10-20). 기존 결정 (b)+(c)는 calc.py에 남기고 화면에서 뺀다 | 메뉴 조회 기능에 집중 |
| D6 | 월 고정비 | 총액 하나 / 항목별 합계 | **보류** (손익분기에만 쓰임) | D5와 같음 |
| D7 | 시나리오 | 개수, 바꿀 수 있는 값 | **보류**. 기존 결정(현재·A·B, % 슬라이더)은 calc.py에 남기고 화면에서 뺀다 | D5와 같음 |
| D8 | 단위·반올림 | 금액 단위, 비율 자릿수 | 계산(1잔 원가 포함)은 분수(정확한 값)로 하고 화면 표시에서만 원 단위 반올림. 비율은 소수 1자리 | 중간 반올림으로 1원 어긋나는 것을 막음 |
| D9 | 저장 | 저장 안 함 / CSV 내보내기·불러오기 | 저장 안 함. 검색 결과도 저장하지 않음. 메뉴·레시피 예시는 menu.csv·recipe.csv(가상 값) | 범위 축소. 실제 판매처 정보를 저장소에 남기지 않음 |
| D10 | 재료 단가 검색 | 검색 출처, 모델, 결과 형식 | 재료마다 네이버 쇼핑 검색 API로 상품 몇 개(상품명·가격·링크)를 받고, NVIDIA 무료 LLM이 관련 없는 상품을 거르고 상품명에서 구매량(레시피와 같은 단위 g/ml)을 읽는다. 그중 단위당 가장 싼 상품의 구매가·구매량·링크를 표에 채우고 사장이 고칠 수 있다. 모델 이름은 단계 4에서 정해 여기에 적는다 | 무료로 실제 판매가와 출처를 얻는다. LLM 판단은 틀릴 수 있어 링크를 보여주고 사람이 확인 |
| D11 | 검색 불가·단가 빈 칸 | 멈춤 / 이유 표시 | 검색 키(네이버·NVIDIA) 없음·검색 실패 시 이유를 보여주고 단가 직접 입력으로 계속. 단가가 빈 칸이거나 구매량이 0인 재료가 있으면 1잔 원가 대신 "계산 불가"와 해당 재료를 표시 | 채점자 등 키가 없는 사람도 앱을 쓸 수 있게 |

## 5. 손 계산 사례 (검증 기대값)

계산기나 스프레드시트로 직접 계산한다. 앱이나 Claude가 낸 값을 옮겨 적지 않는다.
(Claude가 계산기로 검산하기 쉬운 숫자로 작성. 학생 검산: ☐)

공통: 수수료율 2%, 포장비 300원. 단가는 가상의 값.

| 사례 | 종류 | 입력 | 기대 결과 | 계산 과정 |
|---|---|---|---|---|
| R1 | 대표 | 아메리카노(원두 18g, 물 250ml, 얼음 150g). 원두 25,000원/1,000g, 물 0원/1,000ml, 얼음 5,000원/3,000g. 희망 판매가 4,400 | 1잔 원가 1,000원, 1잔 이익 2,912원, 원가율 24.7%, 마진율 66.2% | 재료비 18×25,000÷1,000=450, 250×0÷1,000=0, 150×5,000÷3,000=250 → 700. 원가 700+300=1,000. 이익 4,000−1,000−88=2,912 (C1과 같음) |
| R2 | 대표(나눗셈 나머지) | 카페라떼(원두 18g, 우유 200ml, 얼음 150g). 원두·얼음은 R1과 같음, 우유 2,900원/900ml. 희망 판매가 5,500 | 1잔 원가 1,644원, 1잔 이익 3,246원, 원가율 31.9%, 마진율 59.0% | 우유 200×2,900÷900=644.44. 원가 450+644.44+250+300=1,644.44→표시 1,644. 이익 5,000−1,644.44−110=3,245.56→3,246. 원가율 1,754.44÷5,500=31.90%. 마진율 3,245.56÷5,500=59.01% |
| E3 | 경계(손해) | R1과 같고 희망 판매가 1,000 | 1잔 이익 −111원, 원가율 102.0%, 마진율 −11.1%, 손해 경고 | 공급가 909.09, 수수료 20. 909.09−1,000−20=−110.91→−111 |
| E4 | 경계(단가 없음) | R1에서 얼음 구매량을 0(또는 빈 칸)으로 | 1잔 원가 "계산 불가 — 단가가 없는 재료: 얼음" | 0으로 나눌 수 없음 |
| E5 | 경계(검색 불가) | 검색 키 없이 단가 검색 | "검색 키가 없어 검색할 수 없음 — 단가를 직접 입력하세요" | — |
| C1 | 대표(1잔 이익 함수) | 판매가 4,400, 원가 1,000 | 1잔 이익 2,912원, 원가율 24.7%, 마진율 66.2% | 공급가 4,000. 수수료 88. 4,000−1,000−88=2,912. (1,000+88)÷4,400=24.73%. 2,912÷4,400=66.18% |
