## 0. 출발점 (주제 제안 원문)

> 소규모 카페 사장님이 메뉴 가격을 정할 때 쓰는 웹앱. 재료 원가, 판매가, 예상 판매량을 넣으면 마진과 손익분기점을 보여준다. 주변 카페는 "이 정도로 장사하니까"라는 감으로 가격을 정하는 경우가 많아서, 숫자를 근거로 판단할 수 있게 한다.
> - 기능 1: 메뉴별 원가·마진 계산
> - 기능 2: 월 고정비 기준 손익분기 판매량 계산
> - 기능 3: 가격·판매량 시나리오 비교

교수님 코멘트: 기능 구현은 간단하니 UI/UX 설계에 힘을 실을 것 → 계산은 가볍게, 화면 흐름과 읽기 쉬움에 집중한다.

## 2. 정의 결정

| ID | 결정 | 선택지 | 내 선택 | 이유 |
|---|---|---|---|---|
| D1 | 원가 입력 방식 | (a) 1잔 원가 직접 입력 (b) 재료 구매가·구매량 + 1잔 사용량으로 환산 | (a) 1잔 원가(재료+포장 합계) 직접 입력 | 처음엔 (b)를 골랐으나 일정과 교수님 코멘트(UI/UX 집중)로 범위를 줄임 |
| D2 | 1잔 변동원가에 넣을 것 | 재료 / 포장재 / 판매가 비례 비용(%) / 폐기·손실 | 재료+포장(1잔 원가 한 숫자) + 카드 수수료(%, 앱 전체 하나) | 수수료는 매 잔 붙는 실제 비용. 결제 방식 차이는 평균 비율을 넣어 반영 |
| D3 | 부가세 | (a) 판매가 ÷ 1.1(공급가)로 계산 (b) 무시하고 한계에 적음 | (a) 판매가는 부가세 포함가. 이익은 공급가 기준, 수수료는 판매가 기준. 일반과세자 가정 | 무시하면 1잔 이익이 약 9% 크게 나와 손익분기를 과소평가 |
| D4 | 마진 표기 | 1잔 이익(원) / 원가율 / 마진율 / 마크업 (용어 정의 포함) | 1잔 이익 = 판매가÷1.1 − 원가 − 판매가×수수료율. 원가율 = (원가 + 수수료) ÷ 판매가. 마진율 = 1잔 이익 ÷ 판매가 | 분모를 메뉴판 가격으로 해서 사장이 바로 이해. 원가율+마진율 = 90.9%(나머지는 부가세) |
| D5 | 손익분기 기준 | (a) 메뉴 하나 기준 (b) 판매 비중 가중 전체 잔 수 (c) 손익분기 매출액 | (b)+(c). 손익분기 잔 수 = 고정비 × Σ판매량 ÷ Σ(1잔 이익×판매량). 매출액(부가세 포함) = 고정비 × Σ(판매가×판매량) ÷ Σ(1잔 이익×판매량). 손해 메뉴도 합산하고 경고. Σ(1잔 이익×판매량) ≤ 0 또는 판매량 합 0이면 "손익분기 없음"과 이유 표시 | 메뉴가 여럿인 실제 카페에 맞음. 손해 메뉴를 빼면 손익분기를 과소평가 |
| D6 | 월 고정비 | 총액 하나 / 항목별 합계, 사장 본인 인건비 포함 여부 | 총액 하나. 입력 안내에 "사장 본인 인건비도 포함 권장" | 입력을 가볍게. 본인 인건비 누락 실수는 안내로 막음 |
| D7 | 시나리오 | 개수, 바꿀 수 있는 값. 판매량은 사용자 가정값 | 3개 고정: 현재 + A + B. A·B는 전체 메뉴 판매가 변화(%)와 판매량 변화(%)를 슬라이더로 조정. 월 이익·손익분기 잔 수·매출액을 나란히 비교 | 메뉴마다 고치는 것보다 조작이 쉽고 "가격 올리면 덜 팔려도 남나"에 바로 답함 |
| D8 | 단위·반올림 | 금액 단위, 비율 자릿수, 손익분기 잔 수 처리 | 계산은 분수(정확한 값)로 하고 화면 표시에서만 원 단위 반올림. 비율은 소수 1자리. 손익분기 잔 수·매출액은 올림 | 중간 반올림으로 1원·1잔 어긋나는 것을 막음. 내림하면 손실 구간 |
| D9 | 저장 | 저장 안 함 / CSV 내보내기·불러오기 | 저장 안 함. 앱을 열면 가상 예시 메뉴가 채워져 있음 | 범위 축소. 예시 데이터로 시연이 쉬움 |

## 3. 범위

### 포함
- 사이드바: 월 고정비, 카드 수수료율 입력
- 메뉴 표 편집(메뉴명, 판매가, 1잔 원가, 예상 월 판매량) — 행 추가·삭제 가능

- 가게 전체 월 이익, 손익분기 잔 수·매출액, "손익분기 없음" 이유 표시
- 시나리오 현재·A·B 비교 표와 막대 차트

- 고정비 항목별 입력
- 시나리오 4개 이상, 메뉴별 시나리오 값 편집
- 수요 예측, 저장·CSV, 로그인, 배포
